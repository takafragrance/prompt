# 要件定義：静的ランディングページ（Figma → HTML / CSS / JS）

実装方針は `AGENTS.md`（ponytail）に従う。本ファイルと矛盾する場合は **本ファイルを優先**する。  
マークアップ・CSS・JS の実装仕様は [prompt.md](prompt.md) に従う。実装仕様と本要件が矛盾する場合は **本ファイル（案件要件）を優先**し、実装の書き方は `prompt.md` を優先する。

本文は架空サンプル案件 **NORI** を記入済みの例とする。実案件ではブランド名・目的・セクション構成を差し替える。

本 LP は **コンバージョン（トライアル）** と **AIO / LLMO（AI 検索・LLM への理解・引用されやすさ）** を両立する。見た目は Figma 正、情報の抜き出しやすさは本ファイル正とする。

## 1. 目的・ブランド・ターゲット

### 1.1 サイト概要（サンプル：NORI）

| 項目 | 定義内容 |
| --- | --- |
| サイト名 | NORI（ノリ） |
| 業種 | 中小企業向け業務効率化 SaaS |
| ページ種別 | 1 ページ完結の静的 LP（関連コンテンツへの導線は 7 章） |
| 技術前提 | Figma → `index.php` / `style.css` / `org-top.js` / `images/`（スキル A ルール） |

### 1.2 目的

| 項目 | 定義内容 |
| --- | --- |
| 主目的 | 無料トライアル申込（主 CTA）への誘導 |
| 副目的（製品） | 製品理解（何ができるか・使い方・料金感） |
| 副目的（AIO / LLMO） | 「NORI とは何か」「誰向けか」「料金感」が AI に要約・引用されやすいこと |
| KPI（例） | トライアル申込クリック／完了、AI 回答・概要での言及（測定可能な範囲で） |

2D 静止画とタイポ・セクション構成で価値を伝えれば足りる。3D は採用しない。

### 1.3 ブランド

| 項目 | 定義内容 |
| --- | --- |
| トーン | 簡潔・信頼・業務向き。煽りや過剰な装飾は避ける |
| ブランド信号 | ファーストビューで「NORI」が主視覚として読めること（ナビ文字だけにしない） |
| コピー方針 | 1 セクション 1 メッセージ。専門用語は最小限。**各見出し直下 1〜2 文で結論（PREP）** |

### 1.4 想定ターゲット

| 項目 | 定義内容 |
| --- | --- |
| ユーザー層 | 従業員 10〜100 名規模のバックオフィス担当（経理・総務・情シス兼務を含む） |
| IT リテラシー | 操作説明なしで読めること。デモ操作は必須にしない |
| 主閲覧デバイス | **スマホ優先**。PC も同等に破綻しないこと |
| 流入想定 | 検索広告・紹介・比較記事・**従来検索・AI 検索（AI Overview / ChatGPT 等）** |

未記入の実案件では、デバイスはスマホ優先・説明なしで成立、をデフォルトとする。

## 2. ページ構成・セクション要件

NORI LP のセクション順と必須要素。Figma がある場合は **見た目・レイアウトは Figma 正**。定義文・見出し階層・信頼情報・構造化データの有無は **本ファイル正**（Figma に無い場合は情報設計として追加し、デザインは既存トーンに合わせる）。

| # | セクション | 役割 | 必須要素 |
| --- | --- | --- | --- |
| 1 | Header | ブランド識別・ページ内導線・常時 CTA | ロゴ「NORI」、アンカーナビ（特徴 / 流れ / 料金 / FAQ / 会社情報）、ヘッダー CTA「無料で試す」 |
| 2 | Main Visual | 価値の一言・定義・主 CTA | キャッチ、**定義アンサーブロック**（後述）、短いリード、主 CTA、MV 画像（`images/`）。画像の alt に製品要約を含めてよい |
| 3 | 課題提起 | 共感・現状の痛み | 見出し、課題リスト 2〜4 点。見出し直下に結論 1〜2 文 |
| 4 | 特徴 | 解決策の根拠 | 特徴 **ちょうど 3 点**（見出し + 本文。アイコン可）。各点は自己完結 |
| 5 | 利用の流れ | 導入のハードル下げ・HowTo | ステップ 3〜4（番号 + 見出し + 一文）。手順は HTML 上で順序が読めること |
| 6 | 料金プラン概要 | 価格感・比較可能な表 | プラン 2〜3（名称・価格帯・主な内容）。**比較しやすい表または同等の一覧**を必須 |
| 7 | FAQ | 不安の解消・引用単位 | 質問と回答 **5〜8 組**。回答は 2〜4 文で自己完結。詳細は 4 章 |
| 8 | 信頼・会社情報 | E-E-A-T | 運営会社名、所在地または問い合わせ導線、**ページの内容更新日**、実績・根拠となる数値または事例の短文（サンプル可だが「架空」と分かる場合は明示） |
| 9 | 最終 CTA | 再コンバージョン | 短い締め + トライアル CTA |
| 10 | Footer | 法務・補足・関連 | コピーライト、プライバシー等、会社名、**関連コンテンツへのリンク枠**（7 章） |

共通ルール:

- 各セクションは `section__wrapper--*` / `section__inner--*`（または同等）で組む。詳細は `prompt.md`。
- 1 セクションに複数の独立した訴求を詰め込まない。
- ヒーロー（Main Visual）にカード群・統計ストリップ・浮遊バッジを載せない。**定義アンサーブロックはヒーロー内の本文として許可**（装飾バッジではない）。

### 2.1 定義アンサーブロック（NORI・必須）

ページ上部（Main Visual 内または直下）に、次を **合計おおよそ 150 語以内の日本語テキスト**で、画像に依存せず読める形で置く。

| 含めること | NORI の記入例 |
| --- | --- |
| 製品定義 | NORI は、中小企業のバックオフィス向け業務効率化 SaaS である。 |
| 誰向け | 従業員 10〜100 名規模の経理・総務担当を主な利用者とする。 |
| 何ができる | 申請・承認・経費まわりの手続きを一つの画面で進め、手作業の転記を減らす。 |
| 次の行動 | 無料トライアルから始められる。 |

装飾やアニメに閉じ込めてテキストを出さない。スクリーンリーダーとクローラが同じ文言を取得できること。

## 3. AIO / LLMO 向け情報設計

| 項目 | 要件 |
| --- | --- |
| 結論先出し | 主要 `h2` 直下 1〜2 文でそのセクションの結論を述べる（Point → Reason → Example → Point） |
| 自己完結 | 箇条書き・FAQ 回答・特徴の各項目は、前後を読まなくても意味が通る文にする |
| 質問意図 | 可能なら `h2` / FAQ の質問を、想定クエリに近い自然な疑問文または明確な主題にする（例:「NORI の料金は？」「導入までの流れは？」） |
| 専門用語 | 初出で 100 字以内の定義を添えるか、定義ブロックに含める |
| 数値・根拠 | 料金・実績・期間など引用されやすい具体値は、出典または前提（税別・年契約など）を同じブロックに書く |

## 4. 見出し階層・FAQ・セマンティクス

| 項目 | 要件 |
| --- | --- |
| `h1` | ページに **1 つのみ**。製品名と価値が分かる文言（例:「NORI｜中小企業のバックオフィス業務を効率化する」）。ロゴ画像だけを `h1` にしない場合は、近傍のテキスト `h1` またはロゴに適切な代替テキスト |
| `h2` / `h3` | セクション見出しは `h2`。特徴・ステップ・FAQ 項目は論理的な `h3`。見た目のためだけの見出しタグ乱用禁止 |
| FAQ の HTML | **初期 HTML に質問文と回答全文を含める**。アコーディオンは表示の開閉のみ（クラス付け外し）。JS で回答を後から注入しない |
| FAQ 回答 | 2〜4 文。一文目で結論。宣伝だけの回答にしない |
| リスト・表 | 特徴・手順はリスト、料金比較は `table` または同等の意味が伝わるマークアップ |

## 5. 構造化データ（JSON-LD）

`index.php`（または共通 head）に、表示内容と **矛盾しない** JSON-LD を入れる。未表示の誇大情報をスキーマだけに書かない。

| タイプ | NORI での用途 | 必須 |
| --- | --- | --- |
| `Organization` | 運営会社・公式 URL・ロゴ・`sameAs`（あれば） | 必須 |
| `SoftwareApplication` または `Product` | 製品名、説明、オファー（トライアル／料金概要） | 必須 |
| `FAQPage` | ページ上の FAQ と同一の Q&A | FAQ がある場合は必須 |
| `HowTo` | 「利用の流れ」セクションと対応 | 流れセクションがある場合は必須 |
| `WebPage` | `dateModified`（内容更新日）を信頼セクションと揃える | 推奨 |

---

## 6. 信頼シグナル（E-E-A-T）

| 項目 | NORI での定義 |
| --- | --- |
| 運営主体 | 会社名（サンプル: 株式会社ノリ）。Footer および「信頼・会社情報」に記載 |
| 連絡・所在 | 問い合わせ導線、または所在地の概要 |
| 更新日 | ページ内容の最終更新日を人間が読める位置に表示（スキーマの `dateModified` と一致） |
| 実績・根拠 | 導入社数・削減時間など **具体値を短文で**（サンプル数値可。実案件では実データに置換） |
| 出典・前提 | 料金は税込／税別、年額／月額を明記 |

## 7. サイト構造・関連コンテンツ（1 LP の限界への対処）

1 ページ完結でも、トピック権威は **クラスター前提**で設計する。

| 項目 | 要件 |
| --- | --- |
| 本 LP の位置 | 製品のハブ（ピラー相当）。「定義・料金・導入・FAQ」を自己完結でカバー |
| 関連導線 | Footer または会社情報付近に、想定クエリ向けの関連ページ枠（例: 機能詳細、導入事例、料金詳細、セキュリティ）。未公開ならプレースホルダ URL を要件に残し、実装時は存在するページのみリンク |
| 内部リンク | 関連ページへはテキストリンク。アンカーテキストは主題が分かること |
| 単独公開時 | 関連ページが無い場合でも、本 LP 単体で定義・FAQ・料金・手順が完結していること（本ファイル 2〜6 章） |

## 8. CTA・導線

| 項目 | 定義内容 |
| --- | --- |
| 主 CTA ラベル | 「無料で試す」（文言は Figma があれば Figma 優先） |
| 主 CTA 配置 | Header、Main Visual、最終 CTA に必須。特徴・料金付近への追加は任意 |
| リンク先 | トライアル申込 URL（実案件で指定。サンプルでは `#trial` または外部申込ページ想定） |

## 9. デザイン・素材要件

| 項目 | 定義内容 |
| --- | --- |
| デザイン正 | Figma / キャプチャ / 指示文。独自のデザイン改変や不要機能追加はしない |
| 情報設計の追加 | 定義ブロック・更新日・構造化データなど本ファイル必須項目は、Figma に無くても追加する（トーンは Figma に合わせる） |
| 画像 | すべて `images/` 配下。意味のある `alt`。パス切れ・アスペクト崩れなし |
| レスポンシブ | PC / SP 統合。ブレイクポイント `@media (width <= 768px)`。SP サイズは可能な限り `vw` |
| インナー幅 | PC `1140px`、スマホ `89.3333vw`（CSS 変数で管理） |
| 命名 | BEM。詳細は `prompt.md` |

## 10. 技術面（検索・AI クローラ）

| 項目 | 要件 |
| --- | --- |
| title / description | 製品名 + 誰向け + 価値が分かる一意の `title` と meta description |
| 正規 URL | 意図した canonical（同一内容の重複を作らない） |
| 更新日 | 表示と JSON-LD で一致 |
| robots.txt | 公開意図があるなら主要 AI クローラ（例: GPTBot、Google-Extended）を無闇に全面 Disallow しない。ブロックが必要な場合は案件で明示 |
| llms.txt | サイト直下に `llms.txt` を置くことを推奨。製品概要・主要 URL・連絡先の要約を記載（実案件のドメインに合わせて作成） |
| FAQ / HowTo の可視性 | 構造化データと画面上の文言を一致させる |

## 11. 実装制約（委譲）

次は本ファイルで再定義せず、既存定義に従う。

| 領域 | 参照先 |
| --- | --- |
| 新規サイトの HTML 起点（`php.json`） | ルール `html-css` / スキル `figma-html-css` |
| ファイル構成・HTML 骨格・CSS 変数・BEM・インデント | [prompt.md](prompt.md) |
| JS（`const`/`let`、モジュール化、インライン禁止、`addEventListener`、クラス付け外し） | [prompt.md](prompt.md) およびルール `javascript` |
| 出力範囲・禁止事項・AI 宣言文 | [prompt.md](prompt.md) / ルール `html-css` |

想定する JS 機能（NORI）:

- SP メニューの開閉
- FAQ アコーディオン（**回答テキストは初期 HTML に存在**）
- （任意）スムーススクロール

見た目の制御は CSS クラスの付け外しに寄せる。JSON-LD は静的に出力してよい（JS 必須にしない）。

## 12. 受け入れ条件

次を満たせば要件クリアとする。

1. 目的（無料トライアル誘導）とターゲット（スマホ優先のバックオフィス担当）がページ構成から読み取れる
2. 上記セクション（または Figma + 本ファイルで定義された同等構成）が揃い、各セクションの必須要素がある
3. 主 CTA が Header・Main Visual・最終 CTA にあり、遷移先が定義どおりである
4. Figma（または指定デザイン）に沿った見た目で、独自の装飾改変がない（情報設計必須項目の追加は可）
5. PC / SP（`width <= 768px`）で致命的な崩れがなく、メニューが使える
6. 画像は `images/` 参照で表示され、主要画像のアスペクトが崩れていない
7. JS は `org-top.js` 集約・インライン禁止・ルール準拠である
8. 実装の書き方は `prompt.md`（BEM、変数、インナー幅等）に従っている
9. **定義アンサーブロック**が画像なしで読め、NORI の定義・誰向け・何ができるが分かること
10. **`h1` が 1 つ**で、主要セクションが適切な見出し階層であること
11. FAQ の Q&A が **初期 HTML に全文**あり、回答が自己完結であること
12. **JSON-LD**（Organization、製品、FAQPage、HowTo）が表示と一致していること
13. **会社情報・更新日**があり、料金に税／期間の前提があること
14. **title / meta description** があり、関連コンテンツ枠または単体完結方針（7 章）を満たすこと
