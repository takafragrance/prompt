# React レビュー チェックリスト

視点: 「動くからOK」ではなく、「半年後の自分やチームメンバーが読んで、安全に改修できるコードか」。

---

## 余計なコードが入ってないこと

- 未使用の import / 変数 / コンポーネント / 死んだ分岐がないか。
- 依頼されていない抽象・共通化・ライブラリ追加がないか。
- 既存ヘルパの再実装がないか。同じ処理が複数ファイルに複製されていないか。
- 説明のためのコメントや `TODO` の取り残しがないか。

## 簡潔明瞭

- 名前を見れば役割が分かるか。ファイルを一通り読んで流れが追えるか。
- ネストが深く、条件が頭の中で展開できない箇所がないか。
- 「clever」な省略（隠れた副作用、過剰な三項演算子）で読みにくくなっていないか。

## 脆弱性でないか

- `dangerouslySetInnerHTML` / `innerHTML` / `eval` がないか。ユーザー入力をそのまま HTML や URL に載せていないか。
- 秘密情報（キー、トークン）がソースにないか。
- `localStorage` / fetch 失敗でデータ喪失や白画面になっていないか。
- 外部 URL を `href` / `src` に渡すとき、検証なしで開いていないか。

---

## 1. Hooksの適切な利用

### 依存配列（Dependency Array）は正確か

- `useEffect` / `useMemo` / `useCallback` の依存が足りない、または多すぎないか。
- オブジェクト・関数を依存に入れて無限ループや無駄な再実行になっていないか。
- eslint の依存警告を `eslint-disable` で黙らせていないか。黙らせるなら理由がコメントにあるか。

### 不要な useEffect がないか

- 派生値を `useEffect` + `setState` で同期していないか。render 中に計算できるものはそうする。
- イベント（submit、click）で足りる処理を effect に逃がしていないか。
- 親から来た props を state にコピーして「初期値」以外で使い続けていないか。

### クリーンアップ処理

- 購読、`addEventListener`、timer、AbortController を effect が開始したら、戻り値で解除しているか。
- アンマウント後に `setState` しうる非同期処理に中断があるか。

---

## 2. 状態（State）の管理と配置

### Stateの配置は適切か

- 状態は **使う場所の最も近い共通親** にあるか。高すぎると無関係な子まで再レンダーし、低すぎると同期不能になる。
- 同じ事実を二箇所の state で持っていないか。片方が導出できるなら持たない。
- `useState` で足りるのに Context / reducer / 外部ストアを足していないか。逆に、離れた画面が同じ事実を必要なら、無理なリフトや複製になっていないか。

### Propsのバケツリレー（Props Drilling）

- 使わない中間コンポーネントを何段も props が通過していないか。
- 3 段以上ただ運んでいるなら、合成（children）か、本当に共有が必要なら既存の置き場へ寄せる。新規 Context はレビュー指摘に留め、依頼なしで足さない。

---

## 3. コンポーネントの設計と責務の分離

### コンポーネントが大きすぎないか

- 1 ファイルが「取得・変換・フォーム・一覧・モーダル」を全部抱えて追えない大きさになっていないか。
- リスト行だけが肥大化しているなら `FooItem` に分ける余地があるか。表示専用と入力専用を無理に分けろ、ではない。

### カスタムフックの活用

- 同じ state + effect の塊が複数コンポーネントにコピーされていないか。
- UI と無関係な購読・保存・入力同期はフックに出せるか。逆に、1 回しか使わないロジックを先回りしてフック化していないか。

---

## 4. パフォーマンスの最適化

### 無意味なメモ化の防止

- `useMemo` / `useCallback` / `React.memo` が、実測も再レンダーコストの根拠もなく付いていないか。
- 安い計算を `useMemo` している、またはメモ化した子に毎回新しいオブジェクト/関数を渡して無効化していないか。
- メモ化を足す指摘をするときも、ボトルネックが見える場合に限る。予防のメモ化を推奨しない。

### リストレンダリングの key

- `map` の `key` に配列の `index` を安易に使っていないか。
- 追加・削除・並び替えがあるリストは安定した `id`。`index` は順序が変わらない静的リストの最終手段。

---

## 5. 型安全と堅牢性（TypeScriptを使用している場合）

対象が `.jsx` / 型なし JS なら本項は「対象外」でよい。無理に TS 化を求めない。

### any や過度な as（型アサーション）の排除

- `any`、`as unknown as T`、根拠のない `as T`、不用意な `!` がないか。
- 外部入力（`JSON.parse`、API、`localStorage`）を型断言だけで信頼していないか。形を確認してから使う。

### Propsの型定義

- コンポーネント props に `type Props = { ... }`（または同等）があるか。
- 必須と任意が実態と合っているか。`children` やコールバックの型が `Function` / `any` になっていないか。
