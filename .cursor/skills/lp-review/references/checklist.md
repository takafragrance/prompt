# LP レビュー チェックリスト

前提: 指定（または要件定義）の **ターゲットユーザー視点**で見る。最終目的（例: 無料トライアル、資料請求）達成の **障壁**を探す。

確認できない項目は推測せず「評価不能」。

---

## 1. UX/UI・ユーザビリティ

### ヤコブ・ニールセンのヒューリスティクス（要点）

- システムの状態は分かるか（読み込み、メニュー開閉、エラー）。
- 現実の用語・慣習に合っているか。サイト内で言葉・見た目が一貫しているか。
- ユーザーの操作ミスを防げるか／戻れるか（誤タップしやすい CTA 隣接など）。
- 記憶負荷ではなく、画面上で次の行動が分かるか。
- 柔軟性（ショートカット必須になっていないか）と、最小限で美しいデザインか。
- エラーは平文で原因と次の行動が分かるか。ヘルプが必要なら届くか。

### 視覚的階層

- 視線誘導（F / Z）を意識し、ブランド → 価値 → CTA の順で読めるか。
- 主 CTA が競合要素より目立つか（サイズ・色・余白・位置）。
- 見出し・本文・補助テキストの強弱が論理と一致しているか。

### 認知負荷

- 1 セクション 1 メッセージか。情報過多・同列の強調の連打がないか。
- ナビが直感的か（ラベル、アンカー、SP メニュー）。
- ヒーローに無関係なカード群・統計・浮遊バッジが載っていないか。

## 2. SEO・AIO/LLMO

### 内部構造

- `title` / meta description が一意で、誰向け・何のページか分かるか。
- 見出しが論理的か（`h1` は 1 つ、`h2`/`h3` の飛ばしや見た目目的の乱用がないか）。
- 画像・リンクがルール `markup` どおりか（必須属性、メイン画像原則 1 枚、2 枚目以降 `fetchpriority="low"`、装飾例外、`figure`、裸の `a` 禁止、`target`/`rel`）。

### E-E-A-T

- 運営主体・連絡、更新日、根拠となる数値や前提（税別など）が伝わるか。
- 専門性・経験が本文から読み取れるか（根拠のない自慢だけになっていないか）。

### 検索意図・AI 引用しやすさ

- ターゲット意図（知りたい / 比較したい / 申し込みたい）に対し定義・手順・料金・FAQ が足りるか。
- 定義アンサーブロックや、見出し直下の結論（PREP）があるか。
- FAQ が初期 HTML に全文あるか。回答は 2〜4 文で自己完結か。
- JSON-LD（Organization / 製品 / FAQPage / HowTo 等）がある場合、表示と一致しているか。無い場合は要件上必須なら指摘。
- 詳細は `figma-html-css` の `requirements.md`（AIO/LLMO 章）を正とする。

---

## 3. CRO・コピーライティング

### バリュープロポジション

- 訪問後おおよそ 3 秒で「何のサイトか」「自分にどんな得があるか」が分かるか。
- キャッチとリードが抽象スローガンだけで終わっていないか。

### CTA

- 主 CTA の文言（マイクロコピー）が具体的か（何が起きるか分かる）。
- 配置が Header / ファーストビュー / 終盤など、離脱ポイントをカバーしているか。
- 心理的ハードル（料金不明、個人情報過多の印象、競合リンク過多）を下げているか。
- 副 CTA が主 CTA を埋没させていないか。

## 4. アクセシビリティ（WCAG 観点）

- テキストと背景のコントラストが極端に低くないか（確認不能なら評価不能）。
- 画像の `alt`（または装飾の空 `alt`）、アイコンボタンの名前（テキストまたは `aria-label`）。ルール `markup` も確認。
- キーボードでメニュー・CTA・FAQ 開閉に辿れるか。フォーカスが見えるか。
- 意味が色だけに依存していないか。
- 見出し・ランドマーク（`header` / `main` / `footer` / `nav`）で構造が追えるか。

---

## 5. フロントエンド・パフォーマンス（ソースがある場合）

### Core Web Vitals 意識

- LCP: ヒーロー画像の過剰サイズ、遅延の仕方。メイン画像は原則 1 枚で `fetchpriority="high"`、2 枚目以降は `low`。high に lazy/async が付いていないか。
- CLS: 寸法未指定の画像（`width` / `height` 欠落）、フォントや挿入コンテンツによるガタつき要因。
- インタラクション遅延: メインスレッドを塞ぐ過大な JS、不要な同期処理。
- 実測値がない場合はコード上の明らかなリスクのみ指摘し、ラボ数値は評価不能。

### セマンティクス

- 適切な要素（ボタンは `button` / `a`、リスト、表、見出し）を使っているか。
- `div` / `span` の乱用で意味が消えていないか。
- `<img>` / `<a>` / `target`・`rel` がルール `markup` どおりか。

---

## 6. HTML / CSS / JS 規約（本リポジトリ）

### CSS・命名

- クラスが BEM（`Block__Element--modifier`）に従っているか。
- セクションは `section__wrapper--*` / `section__inner--*`（または同等）か。
- 共通スタイルは `[class*=""]` 等でまとめ、header / footer / section ごとに分けているか。サイト全体への無差別共通化は指摘。
- JS から見た目を操作する対象は、クラス名の先頭を **`js-`** にする（例: `js-menu`、`js-faq-trigger`）。スタイリング専用クラスと混同していないか。

### JavaScript

- `const` / `let` のみ（`var` 禁止）。
- IIFE または ES Modules など、レキシカル環境内で書きグローバルを汚していないか。
- インライン `<script>` / インラインイベント禁止。`addEventListener`。
- `innerHTML` でマークアップ組み立てていないか。DOM は存在確認。
- 見た目は CSS クラスの付け外し。詳細はルール `javascript` / `prompt.md`。

## スコア目安（1〜5）

| 点 | 目安 |
| --- | --- |
| 5 | 重大な障壁なし。軽微な改善のみ |
| 4 | 目的達成は可能だが改善余地あり |
| 3 | 中程度の障壁や欠落が複数 |
| 2 | 目的達成を大きく妨げる問題あり |
| 1 | Critical が複数、または基本構造が破綻 |
| — | 材料不足で評価不能 |
