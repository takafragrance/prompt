# 要件定義：3D ランディングページ

実装方針は `AGENTS.md`（ponytail）に従う。本ファイルと矛盾する場合は **本ファイルを優先**する。

---

## 1. 目的・ターゲット要件

### 1.1 演出の目的（3D を使う理由）

3D を採用する目的を、実装前に次のいずれか（または組み合わせ）として明確にする。目的が曖昧なまま「かっこいいから」では採用しない。

| 目的の例 | 説明 |
| --- | --- |
| ブランドの世界観を伝える | 空気感・空間・没入感をファーストビューで伝える |
| 商品の構造を 360° 見せる | 形状・ディテール・組み立てを立体で理解させる |
| 体験・操作のデモ | プロダクトの使い方や変化をインタラクティブに示す |

- 3D はランディングの主視覚（ヒーロー）または中核セクションに限定し、ページ全体を 3D 化する必要はない。
- 3D を使う理由と、2D（静止画・動画）では不足する点を要件として一文で残す。

### 1.2 想定ターゲット

| 項目 | 定義内容 |
| --- | --- |
| ユーザー層 | 想定する IT リテラシー（操作説明が必要か／見ているだけで成立すべきか） |
| 主閲覧デバイス | スマホ中心か、PC 中心か。両方必須なら優先デバイスを明記する |
| 操作前提 | マウス前提の操作を必須にするか、タッチでも成立させるか |

実装前に上記を確定し、ドキュメントまたは依頼文に記入する。未記入の場合は次をデフォルトとする。

- デバイス: **スマホ優先**、PC も同等に破綻しないこと
- 操作: 説明なしで理解できること。高度な操作は任意の加点とする

## 2. 機能・インタラクション要件

### 2.1 3D の挙動

実装する動きを具体的に定義する。例:

| 挙動 | 内容の例 |
| --- | --- |
| ポインタ追従 | マウスの動きに合わせてモデルが傾く |
| スクロール連動 | スクロールに応じてモデルが回転・移動する |
| クリック反応 | クリック／タップで色や状態が変わる |
| 自動再生 | 読み込み後にアイドルアニメーションをループする |

- 採用する挙動はチェックリストとして列挙し、「必須 / 任意」を分ける。
- 自由回転（OrbitControls 等）や複数操作の同時採用は、目的と衝突しない場合のみ許可する。

### 2.2 フォールバック（代替表示）

次の場合に 3D を出さず代替を表示する仕様を必須とする。

- 3D（WebGL）が読み込めない
- 非対応の古いブラウザ・端末
- （推奨）`prefers-reduced-motion: reduce`

代替手段（優先順を決めて明記する）:

1. **静止画（2D）**
2. **動画**（静止画より重い場合は採用しない判断も可）

代替時も、見出し・説明文・CTA など情報設計上必要な HTML 要素は表示を維持する。ユーザー向けの技術エラー文言は原則出さない。

## 3. デザイン・素材要件

### 3.1 3D モデルの調達方法

| 役割 | 指定 |
| --- | --- |
| モデル制作 | **Spline で自作**する |
| 書き出し形式 | **glTF / GLB** を基本とする |
| ランタイム | 書き出したモデルをサイト側で読み込む（Spline の埋め込みプレイヤーは使わない） |

#### 外部アセットの読み込み

自作が難しい場合は、次の手段でモデルを調達してよい。

- **Spline 内の無料ライブラリ**からアセットを取り込む
- **外部の 3D 素材サイト**からファイルを入手し、Spline またはプロジェクトへインポートする

取り込み可能な形式の例:

- `.gltf` / `.glb`
- `.obj`（必要に応じて Spline 側で取り込み、最終的には glTF / GLB へ書き出してランタイムに渡す）

共通ルール:

- 権利・ライセンス（商用利用・改変・クレジット表記の要否）を必ず確認する
- ランタイム（Three.js）へ渡す配信形式は、原則 **glTF / GLB** に揃える（`.obj` を直接配信する場合は明示する）
- ファイル配置・命名規則はプロジェクト構成に合わせて別途指定する

#### 容量（ポリゴン数）への注意

ゲームや映画向けのリアルすぎる素材（目安として **数万ポリゴン以上**、ファイルサイズが **数十 MB** 級）を読み込むと、LP の表示が非常に重くなる。

- LP 用には、なるべく **「ローポリ（Low-poly）」** や **「Web用」** と明記された軽量素材を選ぶ
- 高ポリ素材しかない場合は、採用前にリダクション（ポリゴン削減）または軽量版への差し替えを行う
- ファイルサイズ・テクスチャ上限は「5. パフォーマンス（軽量化）要件」に従う

### 3.2 視覚効果

次を定義する。

| 項目 | 定義すること |
| --- | --- |
| ライティング | 明るさ・方向・色温度の方針 |
| 影 | 有無。重い場合の疑似影への代替可否 |
| 背景 | 透明にして Web サイトに馴染ませるか、シーン内背景を持つか |
| 合成 | HTML テキストとの重なり、可読性のためのオーバーレイの有無 |

サイト全体のトーン（色・タイポ・余白）と矛盾しないこと。

## 4. JS 構成要件

### 4.1 記述ルール

- `const` または `let` で記述する（`var` は使わない）。
- グローバル汚染を防ぐため、即時関数（IIFE）や **ES Modules** など、適切なレキシカル環境内で記述する。
- インデントは **2スペース** で揃える。
- JS 内に CSS（インラインスタイルの大量付与など）を記述しない。見た目の制御は CSS クラスの付け外しで行う。

### 4.2 保守性・安全性

- `innerHTML` の無闇な使用は避け、`textContent` や `classList` などを用いて安全に実装する。
- DOM 取得時は null チェックを行い、エラーに強いコードにする。

### 4.3 外部ファイルへの集約（インライン禁止）

- HTML 内へのインライン `<script>` は禁止する。処理はすべて `org-top.js`（またはプロジェクトで指定した JS / モジュール）に集約する。
- React プロジェクトでは、ページ初期化・DOM インタラクションを `org-top.js` 等のモジュールに置き、コンポーネントから呼び出す。
- React プロジェクトの 3D シーンは **React Three Fiber（R3F）** で記述する（`Canvas` / 宣言的なメッシュ・マテリアル等）。imperative な Three.js 初期化を React 側に直書きしない。
- HTML 要素へのインラインイベントハンドラ（`onclick=""` / `onload=""` など）は禁止する。
- イベントは JavaScript 側で `addEventListener` を用いて設定する（React の合成イベント・R3F のイベントは可）。

## 5. 開発・実装環境要件

### 5.1 使用ツール・言語

| レイヤ | 指定 |
| --- | --- |
| 3D ランタイム | **Three.js** によるコーディング |
| React 利用時 | **React Three Fiber（R3F）** で記述する（生の Three.js を React コンポーネント内で直接操作しない） |
| モデル制作 | **Spline** |
| 埋め込み方針 | Spline embed / ノーコードツール（STUDIO 等）での 3D 公開は行わない |
| フロント | プロジェクト既存の構成（例: React + Vite）に合わせる。新規フレームワーク導入は依頼がない限り行わない |
| 依存関係 | 原則 `three` を追加する。React プロジェクトでは `@react-three/fiber` を追加する。`@react-three/drei` 等は必要性が明確な場合のみ |

### 5.2 対応ブラウザ・端末

次を必須動作対象とする。

- iOS Safari（直近メジャーを目安）
- Android Chrome（直近メジャーを目安）
- デスクトップの主要ブラウザ（Chrome / Safari / Firefox）

確認観点:

- 3D が表示される、またはフォールバックに切り替わる
- CTA・主要導線が利用できる
- 対象デバイスの縦／横で致命的なレイアウト崩れがない

### 5.3 アクセシビリティ（推奨必須）

- 3D キャンバスは装飾の場合 `aria-hidden` 等で扱い、情報は HTML 側に置く
- キーボードで主要 CTA・ナビに到達できること
- モーション軽減設定時はアニメを抑制、またはフォールバックへ切り替える

## 6. パフォーマンス（軽量化）要件

### 6.1 データ容量・品質の制限

| 指標 | 目標値 |
| --- | --- |
| 3D ファイル合計 | **5MB 以下** |
| テクスチャ解像度 | **最大 2K（2048px）**。可能ならそれ未満を優先 |
| その他 | ポリゴン数・マテリアル数は Spline 書き出し前に削減する |

追加の推奨:

- Three.js およびシーン初期化は必要に応じて遅延読み込みする
- `devicePixelRatio` に上限を設ける
- タブ非表示時は描画ループを停止する

### 6.2 ローディング画面

| 項目 | 要件 |
| --- | --- |
| 要否 | 3D 読み込み中のローディング表示を定義する（有無を明記。重いアセットでは **有** を推奨） |
| デザイン | インジケータの見た目（ブランドに合わせた簡易表示など）を決める |
| 完了時 | コンテンツへ自然に遷移（フラッシュ禁止） |
| 失敗時 | ローディングを終了し、フォールバック（静止画／動画）へ切り替える |

---

## 7. 受け入れ条件

次を満たせば要件クリアとする。

1. 3D を使う目的とターゲット（リテラシー・デバイス）が定義どおりである
2. 定義したインタラクションが動作する
3. 非対応時に静止画または動画のフォールバックが表示される
4. モデルは Spline で制作し、描画は Three.js で行う（React 利用時は R3F で記述する）
5. 3D ファイル合計 5MB 以下、テクスチャ最大 2K を守る
6. ローディング仕様が実装され、必須ブラウザ・端末で閲覧できる
7. JS は `const`/`let`・モジュール化・2スペースインデント・クラス付け外し・`addEventListener` 方針に従う
