# React ランディング デザイン制約

既存デザインシステムや明示 Figma がある場合はそれを優先する。以下は Figma なし／ブランド LP を React で組むときのデフォルト。

実装方針は `AGENTS.md`。本ファイルと矛盾する場合は **本ファイルを優先**する（静的 BEM LP のルールとは混ぜない）。

---

## 1. ファーストビュー

- **1 つの構図**として読めること。ダッシュボードにしない。
- **ブランド先行**: ブランド／プロダクト名がヒーロー級。見出しがブランドを覆い隠さない。
- **ブランドテスト**: ナビを外しても他社のページに見えないこと。
- **ヒーロー予算**: ブランド、見出し 1、短い補足 1、CTA 群 1、支配的な画像 1 のみ。
- 統計・予定・イベント一覧・住所・販促チップ・「今週」枠・メタデータ行をファーストビューに置かない。
- **フルブリード**: ヒーロー画像は端まで支配する平面／背景。inset カード、横パネル、角丸メディアカード、タイルコラージュ、浮遊画像ブロックにしない（既存 DS が明示する場合を除く）。
- **オーバーレイ禁止**: ヒーロー上に切り離しラベル、浮遊バッジ、販促ステッカー、情報チップを載せない。

---

## 2. セクションとカード

- 各セクションは **1 目的・見出し 1・短い補足**。
- **デフォルトはカードなし**。ヒーローにカードを使わない。
- カードはユーザー操作の容器として必要なときだけ。枠・影・背景・角丸を外しても理解が壊れないならカードにしない。
- ピルの塊、統計ストリップ、アイコン列、箱入り販促、スケジュール断片、競合するテキストブロックを増やさない。

---

## 3. タイポ・色・動き

- 表現のあるフォントを使う。Inter / Roboto / Arial / system のデフォルトスタックに寄せない。
- 単色ベタ塗りだけに頼らない。グラデ・画像・薄いパターンで空気感を出す。ただし装飾グラデだけを主ビジュアルにしない（実物・場所・文脈の画像を錨にする）。
- CSS 変数で方向を決める。次の AI 定番ルックは避ける:
  - 紫〜インディゴのグラデテーマ
  - 暖かいクリーム地 + セリフ見出し + テラコッタ
  - 罫線だらけの新聞風マルチカラム
- 安易なダークモード、グロー、`rounded-full` ピル連打、多重シャドウ、絵文字装飾を避ける。
- モーションは存在感と階層のため。意図的なものを **2〜3**。`prefers-reduced-motion` では抑える。

---

## 4. 技術（React）

- Tailwind のユーティリティを `className` に書く。コンポーネント横の新規 BEM 用 `.css` は作らない（既存 CSS モジュールがある画面はそれに合わせる）。
- ネガティブマージン禁止。インライン `style` 禁止。
- ルート追加時は `src/routes.js` の `KNOWN_PATHS` も更新。
- 画像・リンクはルール `markup`。フォーカス・キーボードはルール `a11y`。
- PC とモバイルの両方で破綻しないこと。
